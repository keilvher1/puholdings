# 포항연합기술지주 통합 시스템 운영 매뉴얼

> 최종 갱신: 2026-10-02 (화면 개편 반영) · 대상: 운영 담당자(관리자) 및 입주기업 안내용

---

## 바뀐 점 요약 (2026-10 화면 개편)

화면 모양과 메뉴 위치가 바뀌었어요. **계산 방식·금액·발행 규칙·권한·저장 형식은 그대로**예요. 주소(`/admin/...`, `/portal/...`)도 그대로라 즐겨찾기는 계속 쓸 수 있어요.

| 무엇이 | 예전 | 지금 |
|---|---|---|
| 첫 화면 | 대시보드(숫자 카드) | **홈 = 오늘 할 일**. 처리할 일만 한 줄씩 보이고, 줄을 누르면 그 조건이 걸린 화면으로 가요 |
| 메뉴 이름 | 대시보드 / 사업비 정산 / 관리비 설정 / 문의 관리 | **홈 / 증빙 처리 / 기준 정보 / 문의** (한동안 메뉴에 마우스를 올리면 옛 이름이 보여요) |
| 메뉴 순서 | 홈페이지 관리가 위쪽 | 매달 하는 일 → 입주기업·호실 → 소통 → 홈페이지(접힘). 메뉴 옆 숫자 = 처리할 일 건수 |
| 입주·퇴실 | 관리비 정산 > 설정 > 계약 관리의 [퇴실] | **호실 현황**에서 호실을 눌러 처리. 퇴실은 **입력 → 정산 확인 → 완료 3단계**이고, 실행 전에 받을 돈·돌려줄 금액을 먼저 보여 줘요 |
| 기업 정보 | 표 + 수정 창 | 기업을 누르면 오른쪽에 **기업 카드**(개요·계약·청구·납부·연락처·포털·메모). 포털 계정도 여기서 만들어요 |
| 월 마감 | 4단계 마법사(완료 표시가 브라우저에만 남음) | **이번 마감 카드 + 서버에 저장된 단계 상태**. 새로 고쳐도, 다른 PC에서 열어도 같은 단계가 보여요 |
| 발행 | [일괄 발행 + PDF 메일] 한 번 | 4단계 **발행 전 확인 카드**(건수·합계·납부 기한·자동 점검·확인 필요 기업·PDF 미리보기) → 확인창 → 완료 화면 |
| 납부 기한 | 정하지 않음(모든 청구서 기한 없음) | 4단계에서 **납부 기한**을 정해 발행해요. 포털·메일에 보이고, PDF에는 찍히지 않아요 |
| 청구서 첫 화면 | 이번 달 청구서 목록 | **받을 돈**(월과 상관없이 아직 입금 확인 전인 청구서 전부, 경과일 구간별) |
| 납부 확인 | 1건씩, 이체일 비우면 오늘로 저장 | 여러 건을 체크해 **일괄 납부 처리**, 입금일은 꼭 골라야 해요. 잘못 바꿨으면 **[되돌리기]·[납부 처리 취소]** |
| 수동 청구서 | 같은 달 청구서가 있으면 오류 | **추가 청구 만들기** — 그 달 청구서 상태를 보고 "항목으로 더하기 / 다음 달에 더하기 / 새 수기 청구서" 중 맞는 길을 알려 줘요 |
| 메일이 꺼져 있을 때 | 안내 없음 | 화면마다 "메일은 나가지 않아요"라고 알려 주고, 발행 완료 화면의 주 버튼이 **청구서 PDF 전체 받기(zip)** 예요 |
| 입주기업 포털 | 휴대폰에서 메뉴가 안 보임 | 휴대폰은 **하단 탭 5개**(홈·청구서·프로그램·메신저·계정). 홈 첫 화면에 낼 관리비·기한·**계좌번호 복사** |
| 말투 | "~습니다"·"~하세요" 섞임 | 해요체로 통일. 화면마다 오른쪽 위 **[도움말]** |

자주 쓰는 말(화면과 이 매뉴얼이 같은 말을 써요):

| 말 | 뜻 |
|---|---|
| 작성 중 | 만들었지만 아직 발행하지 않은 청구서. 포털에 보이지 않아요(예전 "초안") |
| 납부 대기 | 발행했고 아직 입금 확인 전인 청구서(예전 관리자 화면의 "발행됨") |
| 기한 지남 | 납부 기한이 지난 납부 대기 청구서(예전 "연체") |
| 받을 돈 | 납부 대기 + 기한 지남 전체(청구월과 상관없이). 포털에서는 "낼 관리비" |
| 정정 중 | 발행했다가 고치려고 되돌린 청구서. 다시 발행할 때까지 포털에 보이지 않아요 |
| 10월분 청구서 | 10월 임대료·관리비 + **9월 사용분** 전기료. 화면에는 "9월 사용분 → 10월 청구"로 보여요 |
| 퇴실 | 계약을 끝내고 호실을 비우는 일(운영 메모의 "퇴거"와 같은 뜻) |
| 자동 인식 | 사진에서 숫자를 읽어 칸을 채워 주는 기능(예전 "AI 판독"). 결과는 제안이고 저장은 직접 눌러야 해요 |

## 1. 시스템 구성과 주소

| 영역 | 주소 | 대상 |
|---|---|---|
| 공개 홈페이지 | https://www.puholdings.co.kr | 누구나 |
| 관리자 | https://www.puholdings.co.kr/admin | 운영 담당자 |
| 입주기업 포털 | https://www.puholdings.co.kr/portal | 입주기업 (계정 발급 필요) |

- 관리자: 관리비 정산·증빙 처리·호실·입주기업·프로그램·메신저·메일 운영 + 홈페이지 콘텐츠 편집.
- 입주기업 포털: 각 기업이 자기 청구서 확인·프로그램 신청·자료 제출·메신저.

## 2. 계정 안내

### 2-1. 관리자 계정

| 항목 | 내용 |
|---|---|
| 로그인 주소 | https://www.puholdings.co.kr/admin/login |
| 현재 계정 | `admin1@puholdings.com` (이름: 관리자) |
| 비밀번호 | 계정 개설 시 설정한 값 (시스템에는 암호화 저장되어 조회 불가) |
| 세션 유지 | 7일 |

- **관리자 추가**: 기존 관리자로 로그인한 상태에서 `/admin/setup` 페이지에서 추가할 수 있어요. (보안상, 관리자가 이미 있으면 로그인하지 않은 상태로는 계정을 만들 수 없어요)
- **비밀번호 분실**: 화면에서 재설정하는 기능은 없어요. 개발 담당자에게 요청해 DB에서 재설정해야 해요.
- 로그인이 끝난 상태에서 관리자 화면 주소를 열면 로그인 뒤 **원래 열려던 화면**으로 돌아가요.

### 2-2. 입주기업 포털 계정

| 항목 | 내용 |
|---|---|
| 로그인 주소 | https://www.puholdings.co.kr/portal/login |
| 계정 단위 | 기업당 1개 |
| 발급 위치 | 관리자 → **입주기업** → 기업을 눌러 **기업 카드** → **연락처·포털** 탭 → [포털 계정 만들기] |
| 발급 안 된 기업 찾기 | 입주기업 목록 위 조건 칩 **"포털 계정 없음"** |

**발급 절차** (관리자):
1. `/admin/tenants` → 기업 행을 눌러 기업 카드를 열고 **연락처·포털** 탭으로 가요.
2. 로그인 이메일(담당자 메일로 미리 채워져 있어요)·담당자 이름을 확인하고 [포털 계정 만들기]를 눌러요.
3. 완료 화면에 포털 주소·로그인 이메일·**임시 비밀번호(한 번만 보여요)** 가 나와요. **[안내문 복사]** 를 누르면 셋을 한 묶음으로 복사하니 문자·카카오톡으로 전달해요.
   닫으려 하면 "안내문을 전달했나요?"를 한 번 더 물어요. 닫은 뒤에는 다시 볼 수 없고, ⋯ → [비밀번호 다시 발급]으로 새로 만들어야 해요.
4. 기업이 임시 비밀번호로 처음 로그인하면 **비밀번호를 새로 정해야** 다른 화면으로 갈 수 있어요.

- 계정이 있으면 카드에 "마지막 로그인 3일 전" 또는 "아직 로그인 안 함"이 보여요.
- 기업 상태가 '퇴실'인 기업은 포털에 로그인할 수 없어요.
- 메일 발송(7장)이 켜져 있으면 만들 때 안내 메일이 가요. **꺼져 있으면 화면에 "안내문을 직접 전달해야 해요"가 보여요.**

## 3. 관리자 메뉴별 사용법

### 3-0. 메뉴 구성(사이드바)

```
홈                         ← 오늘 할 일 합계
매달 하는 일
  관리비 정산               ← 숫자 = 기한 지남 + 정정 중
  증빙 처리                 ← 숫자 = 데스크톱 앱에서 온 확인 필요 증빙
입주기업·호실
  호실 현황                 ← 숫자 = 퇴실 예정
  입주기업
  프로그램                  ← 숫자 = 검토할 제출물
소통
  메신저
  문의                      ← 숫자 = 새 문의
  메일                      ← 숫자 = 최근 30일 보내지 못한 메일(메일 발송이 꺼져 있으면 없음)
▸ 홈페이지 (5)              ← 눌러서 펼침: 사이트 콘텐츠·최신 소식·팝업·포트폴리오·통계
(이름) ▾                    ← 누르면 [홈페이지 보기] [로그아웃]
```

- 메뉴 옆 숫자는 처리할 일 건수예요. 처리하면 줄어요. 숫자는 빨갛게 칠하지 않아요.
- 화면 폭이 좁으면(태블릿·휴대폰) 왼쪽 위 메뉴 버튼으로 같은 메뉴가 열리고, 가운데에 지금 화면 이름(예: "관리비 정산 · 청구서")이 보여요. 관리자 휴대폰 화면은 **조회·납부 처리·메일 결과 확인**까지 쓸 수 있어요. 월 마감은 PC에서 해 주세요.
- 화면마다 오른쪽 위 **[도움말]** 에 순서와 용어 풀이가 있어요.
- 아래 절 번호는 예전 매뉴얼과 같게 두었어요(3-6 관리비 정산 등). 사이드바 순서는 위 그림을 따라요.

### 3-1. 홈 (`/admin`) — 오늘 할 일

로그인하면 처음 보이는 화면이에요. 예전 대시보드의 숫자 카드 대신 **지금 처리할 일**만 보여요.

- **오늘 할 일**: 한 줄 = 할 일 하나. 0건인 줄은 숨어요. 줄 끝 링크를 누르면 그 조건이 걸린 화면으로 바로 가요. 순서는 돈이 걸린 일부터예요.

  | 줄 | 누르면 |
  |---|---|
  | [정정 중] 8월분 청구서 n건 · 다시 발행해야 포털에 보여요 | 월 마감 |
  | 10월분 청구서 22건 · 작성 중 · 발행 전 · 합계 | 월 마감 4단계(발행) |
  | 받을 돈 n건 · 합계 · 기한 지남 n건 · 가장 오래된 ○월분(n일 지남) | 청구서 > 받을 돈 |
  | 데스크톱 앱에서 온 증빙 n건이 확인을 기다려요 | 증빙 처리 |
  | 퇴실 예정 n곳 · 가장 가까운 ○호 날짜 | 호실 현황(퇴실 예정만) |
  | 검토할 제출물 n건 | 프로그램 |
  | 새 문의 n건 | 문의(새 문의만) |
  | 보내지 못한 메일 n건(최근 30일) — 메일 발송이 켜져 있을 때만 | 메일(보내지 못함만) |

- 메일 발송이 꺼져 있으면 목록 아래에 회색 한 줄 "메일 발송이 설정되지 않아 메일은 나가지 않아요. 청구서는 PDF로 직접 전달해요"가 보여요.
- **관리비 마감**: "9월 사용분 → 10월 청구"처럼 지금 마감 중인 달과 4단계 상태(완료·진행 중·시작 전), "4단계 중 3단계 완료"가 보여요. [이어 하기]를 누르면 다음 할 단계가 열려요. 오른쪽 위 [관리비 마감 이어 하기]도 같아요.
- **운영 현황**: 입주율(30실 중 n실), 공실 수, 지난달 수납(n건 중 n건). 누르면 해당 화면으로 가요.
- **메모·확인 사항**: 제목만 보이고, 누르면 그 자리에서 내용·답변 칸이 펼쳐져요. [메모 추가]로 새 메모, ⋯로 해결 표시·되돌리기. 퇴실 처리 결과·추가 청구 할 일 메모도 여기에 쌓여요.
- **홈페이지 현황**(맨 아래, 접힘): 소식·포트폴리오·모집 중 프로그램 수.
- 맨 위 "이번에 바뀐 것 5가지" 안내는 ✕로 닫으면 다시 나오지 않아요.

### 3-2. 홈페이지 > 사이트 콘텐츠 (`/admin/site`)

사이드바 맨 아래 **홈페이지** 묶음을 펼쳐서 들어가요. 공개 홈페이지에 보이는 내용을 편집해요.

| 탭 | 편집 내용 | 반영 위치 |
|---|---|---|
| 설정·텍스트 | 메인 히어로 문구, 연락처(주소·전화), 운영도 소개 문단 | 홈, 하단 푸터, 문의, 회사소개 |
| 연혁 | 연도·날짜·내용 (연도별 자동 그룹) | 회사소개 > 연혁 |
| 조직 구성원 | 팀(경영진/전략기획실/투자사업팀/창업보육팀/벤처파트너)별 이름·직위·역할·이력 | 조직 페이지 |
| 유관기관 | 기관명·로고(업로드 가능)·설명 | 조직 페이지 협력기관 표 |
| 운영도 · 활동 | 한동대/포항연합기술지주/외부 네트워크 활동 항목 | 회사소개 > 핵심 기능 및 역할 |

- 각 항목은 **표시 토글(눈 아이콘)** 로 숨길 수 있고, **정렬 순서**를 정할 수 있어요.
- 저장하면 바로 공개 페이지에 반영돼요. 저장·삭제 결과는 화면 아래 알림으로 보이고, 삭제는 확인창을 한 번 거쳐요.
- 여기 "연락처" 전화번호가 입주기업 포털의 문의 전화번호로도 쓰여요.

### 3-3. 최신 소식 / 팝업 / 포트폴리오 / 통계(홈페이지 묶음) · 문의(소통 묶음)
- **최신 소식**: 글 작성·수정, 파일 첨부(PDF/HWP/이미지 등). 첨부는 홈페이지에서 다운로드·미리보기 가능.
- **팝업**: 기간·우선순위를 정해 홈페이지 팝업 노출. 소식과 연결할 수 있어요. 입주기업 포털에는 팝업이 뜨지 않아요.
- **포트폴리오**: 투자기업 정보·로고 관리.
- **통계**: 홈 화면 숫자(입주기업 수, 누적 매출 등) 수정.
- **문의**(사이드바 "소통"으로 옮겼어요): 홈페이지 문의 접수 내역. 새 문의 건수가 메뉴·홈에 보여요. 접수되면 메신저 "시스템 알림" 토픽에도 남아요. (메일 발송이 켜져 있으면 알림 메일도 가요)

### 3-4. 입주기업 (`/admin/tenants`)

기업 정보·청구서 받을 메일·포털 계정을 한곳에서 관리해요. **입주·퇴실과 호실은 호실 현황(3-5)에서** 처리해요.

**목록**
- 위쪽 검색칸(기업명·대표·사업자번호·호실)과 상태 탭 **입주 중 / 퇴실 / 전체**(기본 입주 중).
- 조건 칩: **포털 계정 없음 · 청구서 받을 메일 없음 · 받을 돈 있음**. 누르면 그 기업만 모여요. [조건 지우기]로 풀어요.
- 열: 기업 · 호실(계약 기준) · 청구서 받을 메일 · 포털 계정(마지막 로그인) · 받을 돈.
- 행 끝 ⋯: 정보 수정 · 포털 계정 · 기업 상태를 '퇴실'로 바꾸기 · 삭제.

**기업 카드**(행을 누르면 오른쪽에 열려요)
- 머리: 호실 · 입주일 · 받을 돈(건수·합계) · 포털 계정 상태.
- 탭: **개요**(다음에 할 일·기본 정보·최근 청구 3건) / **계약**(호실·면적×단가·관리비·보증금, [호실 현황에서 퇴실 처리 ›] [계약 조건 고치기 ›]) / **청구·납부**(최근 12개월, 받을 돈·가장 오래된 기한, [납부 안내 문구 복사]) / **연락처·포털**(연락처, 포털 계정, 최근 메일 5건) / **메모**(기업 메모를 바로 고쳐 저장).
- 청구서 행을 누르면 그 청구서 상세가 열려요.

**정보 수정**(카드의 [정보 수정])
- 기본 정보(기업명·사업자번호·대표자) / 연락·청구 메일 / 기타(더 받은 금액(과납)·메모).
- **청구서 받을 메일**: 발행 메일이 이 주소로 가요. 비우면 담당자 메일로 가요. **납부 안내 메일은 담당자 메일**로 가요.
- 사업자번호(숫자 10자리)·메일 형식이 틀리면 칸 아래에 오류가 보이고 저장되지 않아요.
- 호실·입주일은 계약에서 가져온 값이라 여기서 고칠 수 없어요(호실 현황에서 처리).
- "더 받은 금액(과납)"은 기록용 숫자예요. 청구서에서 자동으로 빠지지 않아요.

**기업 상태를 '퇴실'로 바꾸기 vs 퇴실 처리**
- **퇴실 처리**(호실 현황): 계약을 끝내고 호실을 비워요. 청구가 멈춰요.
- **기업 상태를 '퇴실'로 바꾸기**(여기): 기업 표시만 바꿔요. 포털 로그인과 납부 안내가 끊겨요. **진행 중 계약이 있으면 막혀요**(먼저 호실 현황에서 퇴실 처리).
- 퇴실한 기업은 **삭제하지 말고** 상태만 바꿔 주세요. 삭제하면 그 기업의 청구서·계약·신청 기록이 모두 영구 삭제돼요. 삭제 확인창에 지워질 건수가 보이고, 확인 체크를 해야 삭제돼요.

### 3-5. 호실 현황 (`/admin/rooms`) — 입주·퇴실 처리

건물 > 층별 호실 보드예요. **입주·퇴실은 여기서만** 처리해요.

| 모양 | 상태 |
|---|---|
| 흰 칸 + 기업명 | 입주 중 |
| 주황 테두리 + "10월 31일 퇴실 · n일 남음" | 퇴실 예정 (계약 종료일 기준) |
| 점선 테두리 + "공실" | 공실 |
| 회색 빗금 + "사용 불가" | 사용 불가(기준 정보 > 호실에서 지정) |

- 맨 위 입주율(30실 중 n실)과 상태 칩(전체·입주 중·퇴실 예정·공실·사용 불가). 칩 숫자 = 누르면 보이는 칸 수예요.
- 검색칸에 기업명·호실을 넣으면 맞는 칸만 진하게 보여요.
- 칸을 누르면 오른쪽에 호실 정보가 열려요. 칸에 따라 [입주 처리] 또는 [퇴실 처리]가 있어요.

**입주 처리**(공실 칸 → [입주 처리])
1. **누가·언제**: 입주 기업을 검색해 골라요. 목록에 없으면 "○○ 새 기업으로 등록"을 골라 기업명·사업자번호·청구서 받을 메일을 그 자리에서 넣어요. 입주일.
2. **얼마**: 부과 면적(호실 면적으로 채워져요)·평당 임대료(신규 입주 21,000원, 공장동 15,000원)·관리비(15,000원, 공장동 30,000원)·받은 보증금([이 금액 넣기] = 면적 × 20만 원). 아래에 "매달 청구 예상"이 계산돼요.
3. **어떻게 청구**: 전기료(면적으로 나눠 내기 — 본관 / 계량기 사용량대로 — 공장동), 첫 달(**한 달 전액**이 기본 / 입주일부터 날짜만큼(일할) / 첫 달은 청구 안 함). 입주한 달 청구서에는 전기료가 붙지 않아요.
4. [○호 입주 처리하기] → 완료 카드에 다음 할 일(포털 계정 만들기·청구서 받을 메일 확인·사업자번호 채우기)이 나와요.
   - 그 달 청구서가 아직 발행 전이면 "첫 청구서는 월 마감 3단계에서 들어가요", 이미 발행됐으면 [추가 청구 만들기]로 따로 청구하라고 알려 줘요.
- 빈칸이 있으면 칸 아래에 빨간 글자로 알려 주고 저장하지 않아요. 입주일이 다음 달 이후면 경고가 떠요 — **입주하는 달에 처리**해 주세요.

**퇴실 처리**(입주 중 칸 → [퇴실 처리]) — 3단계
1. **입력**: 퇴실일, 마지막 달(**한 달 전액**이 기본 / 퇴실일까지 날짜만큼(일할) / 마지막 달 청구 안 함), 보증금 반환(아직 돌려주지 않았어요 / 돌려줬어요 → 반환일·금액).
2. **정산 확인**("이대로 퇴실 처리할까요?"): 실행 **전에** 보증금 · 받을 돈(이 기업 전체의 납부 대기·기한 지남) · **돌려줄 금액 = 보증금 − 받을 돈**을 보여 줘요. 받을 돈이 더 많으면 "받을 돈이 n원 남아요"로 보여요.
   - "처리하면" 상자: 호실이 바로 '공실'로 바뀌고 **되돌릴 수 없어요**. 작성 중 청구서·원상복구비·마지막 달 전기료는 이 계산에 들어가지 않아요.
   - **결과를 메모로 남기기**(기본 켬): 홈 메모에 정산 결과 한 줄이 남아요.
   - **기업 상태도 '퇴실'로 바꾸기**(선택): 그 기업에 다른 진행 중 계약이 없을 때만 고를 수 있어요. 바꾸면 포털에 로그인할 수 없어 남은 청구서를 볼 수 없어요.
   - 같은 기업이 다른 호실도 쓰고 있으면 "다른 진행 중 계약" 안내가 나와요. 보증금 상계는 마지막 계약을 퇴실할 때 해요.
   - 퇴실 달 청구서가 이미 한 달 전액으로 발행됐는데 일할을 고르면, 월 마감에서 정정이 필요하다고 알려 줘요.
3. **완료**: "보증금 − 받을 돈 = 돌려줄 금액" 결과 카드 + [복사] [인쇄]. 남은 일: 원상복구비가 있으면 **추가 청구 만들기**(3-6 청구서), 보증금을 돌려준 뒤 반환일·금액은 메모로 남겨 주세요(반환 기록 화면은 아직 없어요).
- 퇴실일이 다음 달 이후면 경고가 떠요 — **퇴실하는 달에 처리**해 주세요(지금 처리하면 오늘부터 공실로 보이고 아직 만들지 않은 청구서에서 임대료가 빠질 수 있어요).
- 계약 조건(면적·단가)을 고치려면 호실 정보의 [계약 조건 고치기]를 눌러요(관리비 정산 › 기준 정보로 가요).

### 3-6. 관리비 정산 (`/admin/billing`) ⭐ 핵심 업무

기존 엑셀 정산표를 대체해요. 하위 탭 3개: **월 마감 / 청구서 / 기준 정보**(예전 "설정").

#### 개념 정리
- **청구 시점 규칙**: **10월분 청구서 = 10월 임대료·관리비 + 9월 사용 전기료**. 화면에는 "9월 사용분 → 10월 청구"로 보여요. 월 마감은 **전기를 쓴 달(사용월)** 을 기준으로 해요.
- **임대료** = 부과 면적(평) × 평당 단가 (신규 입주·갱신 21,000원 / 비갱신 기존 계약 20,000원 / 공장동 15,000원 — 계약별 수정 가능)
- **관리비** = 호실당 정액 15,000원 (공장동 30,000원, 계약별 수정 가능)
- 공급가액 = 부가세 포함액 ÷ 1.1 반올림, 부가세 = 차액 → **합계가 1원도 어긋나지 않아요**
- **전기료 배분**: 한전 청구금액 → 공장동(A, 계량기 실사용) · 사무실 기업(B, 10평당 단가) · 센터(C) 3몫으로 나눠요
- 공장동 kWh 단가 = 한전 고지서 사용단가 × 1.1 (원 단위 반올림)
- **공실은 자동으로 빠져요** (청구서 만들기, 전기료 분모 모두)

#### 매월 마감 루틴 (월 마감 탭)

**화면 맨 위 "이번 마감" 카드**가 늘 지금 마감 중인 달을 말해 줘요. 예: "2026년 9월 사용분 → 10월분 청구서 · 검침 4개 중 4개 입력 · 배분 확정(10평당 86,110원) · 작성 중 22건 · 발행 0건 · 납부 0건 · **다음 할 일: 4단계 발행**".
- 카드 아래 4칸(검침 입력 · 전기료 배분 · 청구서 만들기 · 발행)에 단계마다 **완료 / 진행 중 / 시작 전 / 확인 필요**가 보여요. 이 상태는 **서버에 저장된 값**으로 그려서, 새로 고치거나 다른 PC에서 열어도, 홈의 "관리비 마감" 줄과도 같아요.
- 다른 달은 카드 오른쪽 ◀ ▶ 또는 월 목록(달마다 "발행 완료", "작성 중 22건" 같은 상태가 붙어 있어요)에서 골라요. 지난달을 열면 "지난 달을 보고 있어요" 경고가 떠요.
- "준비할 것: 한전 고지서(공장동 사용단가·청구금액), 공장동 계량기 사진 4장".
- 각 단계 아래 고정 바에 주 버튼이 하나 있어요. 바꾼 값이 있으면 **"○○ 저장하고 다음"**, 없으면 **"다음: ○○"**. 저장하지 않은 채로 다른 달로 가려 하면 확인창이 떠요.
- 중간에 끊겨도 돼요. 저장한 값은 남고, 다시 들어오면 "다음 할 일" 단계가 열려요.

1. **검침 입력** — 계량기 4개(공장동 전체(MAIN)·F101·F103·냉난방기) 표에 **이번 달 지침**(누적 숫자)을 넣어요. 지난달 지침·사용량·**평소(최근 3개월)** 가 옆에 보여요.
   - 상태 칸: 정상 / **확인 필요**(평소보다 50% 넘게 다름) / **오류**(지난달보다 작음 — 자릿수 확인. 이대로는 청구서를 만들 수 없어요).
   - MAIN에는 "F102 요금에 영향"이 붙어 있어요. F102는 계량기가 없어 MAIN에서 나머지를 빼서 계산하니 MAIN을 가장 신경 써서 확인해 주세요.
   - 냉난방기 사용량은 F101·F103에 절반씩 자동으로 더해지고, 청구액은 천 원 미만을 버려요(엑셀과 같음).
   - **[사진으로 채우기]**: 계량기 사진(최대 8장)과 한전 고지서 사진을 올리고 [사진 읽기]를 누르면 숫자를 자동 인식해요. 항목마다 확신(확실/보통/불확실)과 비고가 보이고, **[칸에 채우기]를 눌러도 아직 저장이 아니에요** — 숫자를 눈으로 확인한 뒤 [검침 저장하고 다음]을 눌러야 반영돼요. 자동 인식으로 채운 칸에는 "자동 인식" 표시가 붙어요. 원본 사진은 근거로 보관돼요.
     자동 인식이 꺼져 있으면(`OPENAI_API_KEY` 없음) 버튼 대신 "자동 인식이 설정되지 않았어요 — 직접 입력해 주세요"가 보이고, 표에 직접 넣으면 돼요.
   - 잘 읽히는 사진: 숫자판이 화면을 가득 채우게, 정면에서. 이름표(F101·동력·냉난방)가 같이 나오면 계량기를 자동 구분해요. 기계식은 **빨간 마지막 자리를 뺀** 정수부만 읽어요.
2. **전기료 배분** — 한 열로 넣어요.
   - **한전 청구금액**: 아래에 지난달·작년 같은 달 금액이 보이고, 지난달과 30% 넘게 다르면 "자릿수를 확인해 주세요".
   - **공장동 kWh 단가**: 고지서의 사용단가를 도우미 칸에 넣으면 "× 1.1 = 저장될 값"을 계산해 줘요. [지난달 값 쓰기]도 있어요. 값이 저장되지 않은 달은 칸이 비어 있어요(예전처럼 102원이 미리 들어가지 않아요).
   - 면적별 배분율(기본 70%)은 "고급 설정" 안에 있어요.
   - 결과 3칸(공장동 A · 사무실 기업 B · 센터 C)과 **10평당 청구단가 제안**(10원 단위). 확정단가가 저장돼 있지 않으면 **"제안값으로 확정"** 체크가 켜져 있어요. 이미 저장된 확정단가가 있으면 그 값을 그대로 두고, 지금 제안과 다르면 둘 다 보여 줘요(바꾸려면 직접 골라요).
   - 검산 줄: "배분이 맞아요" 또는 문제 원인 한 문장(예: 센터 부담이 음수).
   - 빈칸은 0으로 저장되지 않고 칸 오류로 막혀요. 확정 없이 저장하려 하면 "10평당 단가를 확정하지 않고 저장할까요?" 창에서 [제안값으로 확정하고 저장] / [확정하지 않고 저장] / [닫기](저장 안 함) 중 골라요.
3. **청구서 만들기** — [청구서 만들기]를 누르면 기업별 청구서가 **작성 중**으로 만들어져요(포털에 아직 안 보여요). 여러 번 눌러도 안전하고, 누를 때마다 최신 값으로 다시 만들어요.
   - 위 요약: 작성 중 n건 · 합계 · 지난달보다 n% · **확인 필요 n건**.
   - 표는 기본 **[확인 필요]** 만 보여 줘요(지난달보다 크게 달라진 곳 · 신규 · 0원 · 전기료 0원). 열: 기업 · 지난달 · 이번 달 · 증감 · 사유("9월 15일 입주 · 일할", "신규" 등) · [미리보기](오른쪽에 PDF). [전체]로 모두 볼 수 있어요.
   - 1·2단계를 저장하지 않았거나 검산이 맞지 않으면 만들기 전에 막힘 안내와 [n단계로 가기]가 떠요. 전기료가 0원으로 계산되는 경우에는 "전기료가 아직 계산되지 않았어요" 창의 주 버튼이 **[전기료 입력하러 가기]** 예요.
4. **발행** — **"10월분 청구서를 보내기 전에 확인해요"** 카드를 위에서부터 읽어요.
   - **나가는 것**: 청구서 n건 · 합계 · (메일이 켜져 있으면) 메일 n곳 · 이메일 없음 n곳. 메일이 꺼져 있으면 "메일 발송이 설정되지 않았어요. 발행하면 입주기업 포털에만 보이고, PDF는 직접 보내야 해요."
   - **납부 기한**: 날짜를 골라요. 기본값은 지난번 발행과 같은 규칙(예: 다음 달 10일), 기록이 없으면 청구월 말일이에요. 포털(메일이 켜져 있으면 메일에도)에 이 날짜가 보이고, **PDF에는 찍히지 않아요**. 이미 기한이 있는 청구서(정정 재발행 등)는 원래 기한을 그대로 둬요. 비어 있거나 오늘보다 앞이면 발행할 수 없어요.
   - **자동 점검**: 검침 4개 중 4개 입력 · 배분 정상 · 10평당 단가 확정 · 전기료 0원 청구서 없음 · 이메일 없는 기업.
   - **3단계 '확인 필요' n건**: 기업명·증감·사유가 그대로 나열돼요. [3단계에서 보기 ›]로 돌아가 확인할 수 있어요.
   - **변동이 가장 큰 기업 청구서**: 카드 안에 PDF가 바로 보여요. [다른 기업 고르기]로 바꿔 볼 수 있어요.
   - 아래 바의 **[22건 발행하기]** 를 누르면 확인창 "10월분 청구서 22건을 발행할까요?"가 떠요(처음 포커스는 [닫기]). 확인창에 건수·합계·메일·납부 기한과 발행하면 생기는 일이 적혀 있어요. 처리 중에는 "발행 중… 창을 닫지 마세요".
   - **완료 화면**: "10월분 22건을 발행했어요" + 발행 n건 · 합계 · 메일 보냄/보내지 못함/이메일 없음(메일이 꺼져 있으면 "메일: 나가지 않았어요"). 새로 고쳐도 다시 보여요.
     - **메일이 꺼져 있으면 주 버튼이 [10월분 PDF 전체 받기(zip)]** 예요 → 받아서 기업에 직접 전달해요(4장·5장 참고).
     - 다음 할 일: "입금이 확인되면 청구서 화면에서 납부 처리해 주세요" [받을 돈 보기].
   - 발행 중 끊기거나 시간이 초과되면 같은 버튼을 다시 누르지 말고, 화면이 다시 읽어 온 "n건 중 n건 발행됨"을 확인해요.
   - 발행 후에는 임대료·관리비·전기료 항목을 고칠 수 없어요(아래 정정 절차).

> ⚠️ **순서가 중요해요.** 1·2단계(검침·전기료 배분)를 **먼저 저장**하고 3단계로 가세요. 화면이 저장 안 된 단계를 막고, 전기료 0원이면 발행 전 경고로 한 번 더 막지만,
> 굳이 [0원으로 진행]을 고르면 전기료 0원 청구서가 그대로 나가요. **이미 발행된 청구서는 [청구서 만들기]로 다시 만들어지지 않아요.**

#### 발행한 뒤 고쳐야 할 때 (정정)
예: 전기료가 빠진 채 발행했거나, 발행 뒤에 한전 금액·검침을 고쳐야 할 때.

1. 월 마감에서 그 **사용월**을 열어요. 발행된 달은 1·2단계가 **읽기 전용**이고 위에 "이 달은 발행됐어요 [정정 시작]"이 보여요. (발행 뒤 전기 값이 바뀐 흔적이 있으면 "발행 뒤 전기 값이 바뀌었어요" 경고가 떠요.)
2. **[정정 시작]** 을 눌러요. 이 버튼은 아무것도 저장하지 않고 1·2단계 잠금만 풀어요(그만두려면 [정정 그만두기]).
3. 1·2단계 값을 고쳐 저장해요.
4. 3단계 **[청구서 다시 만들기]** → "발행된 n건에 최신 값이 반영되지 않았어요" 안내의 **[발행된 n건 되돌려 다시 만들기]** → 확인창 "발행된 n건을 고쳐서 다시 보낼까요?"
   - **정정 사유**를 골라요(검침 입력 오류 / 한전 금액 정정 / 계약·단가 변경 / 기타). 각 청구서 메모에 "정정 사유: …"가 남아요.
   - 되돌린 청구서는 **정정 중**(작성 중)이 되고, 다시 발행할 때까지 포털에 보이지 않으며 받을 돈 목록에서는 "정정 중"으로 따로 보여요. 기존 PDF는 폐기되고, 납부 기한·메모·조정 항목은 남아요.
   - **납부 완료와 수기 청구서는 바뀌지 않아요.**
   - [그대로 두기]를 누르면 아무것도 바뀌지 않아요.
5. 3단계 표에서 금액을 확인하고 4단계에서 다시 발행해요. 메일이 켜져 있으면 제목에 [정정]이 붙어 다시 나가고, 꺼져 있으면 **새 PDF를 받아 직접 다시 전달**해요.

정정 중 청구서가 있는 동안 홈 맨 위와 관리비 정산 메뉴 숫자에 계속 보여요.

#### 청구서 탭 (`/admin/billing/bills`)
위쪽 보기 3개: **받을 돈 / 월별 청구서 / 작성 중**. 오른쪽 위 [추가 청구 만들기].

- **받을 돈**(기본): 청구월과 상관없이 아직 입금 확인 전인 청구서 전부(납부 대기 + 기한 지남).
  - 구간 카드 5개: **기한 전 · 1~30일 지남 · 31~60일 지남 · 60일 넘게 지남 · 기한 없음**(건수·합계). 누르면 그 구간만 보여요.
  - 정정 중 청구서가 있으면 카드 아래 따로 묶여 보여요("다시 발행해야 포털에 보여요").
  - 표: 기업 · 청구월 · 금액 · 납부 기한 · **경과**("22일 지남" / "8일 남음" / "발행 후 n일") · 상태. 오래된 것부터.
  - 기업 이름 검색, 조회 건수·합계가 오른쪽에 보여요.
- **월별 청구서**: 청구월을 골라(◀ ▶) 상태 탭(전체·작성 중·납부 대기·기한 지남·납부 완료)으로 봐요. ⋯ 메뉴에 **그 달 PDF 모두 받기(zip)** · **정산표 엑셀(작성 중 포함)**.
- **작성 중**: 아직 발행하지 않은 청구서만.
- 조건(탭·구간·검색)은 주소에 남아서 새로 고쳐도, 링크로 보내도 같은 화면이 열려요.

**납부 처리(일괄)**
1. 통장에서 입금을 확인한 청구서 행을 체크해요(납부 대기·기한 지남 행에만 체크칸이 있어요). 아래에 "n건 선택 · 합계"가 고정돼요.
2. [납부 처리] → 대화상자에서 **모두 같은 날짜**에 통장에 찍힌 입금일을 넣어요([오늘] 버튼도 있어요). **기본값이 없어 꼭 골라야 해요.** 건마다 날짜를 따로 고칠 수 있고, 빼고 싶은 건은 체크를 풀어요.
3. 메모(선택, 예: "입금자명 솔바람")를 적으면 각 청구서 메모 뒤에 덧붙어요.
4. [n건 납부 완료로 바꾸기]. 입금일이 발행일보다 앞서거나 오늘보다 뒤면 주황 경고가 떠요.
- **되돌리기**: 처리 직후 알림의 **[되돌리기]**, 또는 나중에 청구서 상세 ⋯ → **[납부 처리 취소]** → "납부 대기로 되돌릴까요?" 확인. 납부일 기록이 지워지고 메모에 취소 기록이 남아요.
- 1건만 처리할 때도 행 ⋯ → [납부 처리]로 같은 대화상자를 써요.

**청구서 상세**(행을 누르면 오른쪽에 열려요)
- 머리 "(주)솔바람테크 · 2026년 8월분" + 상태(예: 기한 지남 · 22일 지남). 청구 금액 · 납부 기한 · 발행일 · 받는 메일.
- 항목 표. **작성 중이면 조정 항목(할인·차감·추가)만** 더하거나 고칠 수 있어요. 임대료·관리비·전기료 항목은 읽기 전용이에요 — 바꾸려면 계약·단가를 고친 뒤 월 마감 3단계에서 다시 만들어요.
- 상태별 버튼: 작성 중 정기 청구서 = "월 마감 4단계에서 발행해요" / 작성 중 **수기** 청구서 = [이 청구서만 발행하기] / 납부 대기·기한 지남 = [납부 처리], ⋯(PDF 미리보기 · 납부 기한 바꾸기 · 메모 고치기 · 납부 안내 문구 복사) / 납부 완료 = ⋯(PDF · 납부 처리 취소).
- **[납부 안내 문구 복사]**: "○○ 8월분 관리비 n원이 아직 입금 확인 전이에요. 하나은행 … 로 보내 주세요. 문의 054-279-8710" 같은 문장을 복사해 문자·카카오톡으로 보내요. 메일이 꺼져 있을 때 독촉 수단이에요(기업 카드 청구·납부 탭에도 있어요).

**추가 청구 만들기**(예전 "수동 청구서 만들기")
퇴실 정산·원상복구비처럼 정기 청구서 밖에서 받을 돈을 넣어요. 기업(퇴실 기업 포함)과 청구월을 고르면 그 달 상태에 맞춰 길을 알려 줘요.
- 그 달 **작성 중** 청구서가 있음 → [그 청구서에 항목으로 추가](조정 항목).
- 그 달 청구서가 **이미 발행됨** → 다음 달 작성 중 청구서가 있으면 [다음 달 청구서에 항목으로 추가], 없으면 [할 일 메모로 남기기](홈 메모).
- **진행 중 계약이 있고 그 달 청구서를 아직 만들지 않음** → 막아요. 지금 수기 청구서를 만들면 월 마감에서 그 기업의 정기 청구서(임대료·관리비·전기료)가 만들어지지 않기 때문이에요. 월 마감 3단계에서 먼저 만든 뒤 항목으로 추가해요.
- 진행 중 계약이 없는 기업(퇴실 정산 등)이고 그 달 청구서가 없음 → **새 수기 청구서**. [작성 중으로 저장] 또는 [저장하고 발행하기](확인창).

**청구서 PDF 일괄 다운로드(zip)**
- 월별 청구서 ⋯ → **그 달 PDF 모두 받기**, 또는 월 마감 4단계·완료 화면의 **PDF 전체 받기(zip)**.
- 파일명은 `청구서_YYYY-MM.zip`, 안쪽은 `YYYY-MM_기업명.pdf`(기업별 한 파일).
- 발행된 건은 **발행할 때 만든 그 PDF**(메일이 나갔다면 첨부와 같은 파일)를 담아요. 작성 중인 건은 지금 내용으로 바로 만들어서 건수가 많으면 시간이 걸려요(1건당 약 1.5초).
- 일부가 빠지면 화면에 "n건 중 n건만 받았어요"가 뜨고 zip 안 `_안내.txt`에 명단이 남아요.

**자동 안내**: 납기 3일 전 납부 안내 메일, 납기가 지나면 자동으로 기한 지남 전환 + 안내 메일(7장의 `CRON_SECRET`과 메일 설정 필요). 메일의 "청구서 보기" 링크는 포털의 그 청구서로 바로 열려요.

#### 기준 정보 탭 (`/admin/billing/settings`, 예전 "설정")
안쪽 탭 4개: **단가·기본값 · 계약 · 호실 · 가져오기·내보내기**.
- **단가·기본값**(읽기 위주): 지금 쓰는 평당 임대료·관리비와 그 값을 쓰는 계약 수([이 단가 쓰는 계약 보기]), 단가 규칙, 공장동 kWh 단가(최근 적용값, 실제 입력은 월 마감 2단계), 면적별 배분율, 입금 계좌(PDF·포털 표시, 이 화면에서는 바꿀 수 없어요).
- **계약**: 기업명 검색. 계약을 누르면 오른쪽에서 고쳐요 — 누가·어디(기업·호실은 읽기 전용, 호실을 옮기려면 퇴실 후 새 입주 처리) / 얼마(부과 면적·평당 임대료·관리비·받은 보증금, "월 임대료 = 면적 × 단가"가 같이 보여요) / 어떻게 청구(전기 방식·첫 달·마지막 달).
  - 평당 단가: 갱신·신규 입주 21,000원, 비갱신 기존 계약 20,000원, 공장동 15,000원. 기준 보증금 = 평당 20만 원 × 면적, 받은 보증금은 직접 입력.
  - 고친 조건은 **다음에 만드는 청구서부터** 들어가요. 작성 중 청구서에 넣으려면 월 마감 3단계에서 다시 만들어요. 이미 발행한 청구서는 바뀌지 않아요.
  - 계약 행 ⋯의 **[호실 현황에서 퇴실 처리 ›]** 를 누르면 호실 현황의 그 호실 퇴실 흐름이 열려요(여기서는 퇴실을 하지 않아요).
- **호실**: 호실 추가·면적 수정·사용 불가 지정만 해요. 입주·공실 상태는 호실 현황에서 봐요.
- **가져오기·내보내기**: **월별 정산표 엑셀 내려받기(작성 중 포함)** — 매월 백업용. 기존 정산 엑셀 가져오기는 처음 설정할 때만 쓰고, 반영 전에 "기업 n · 계약 n · 호실 n을 반영할까요?" 확인을 거쳐요.

### 3-7. 프로그램 (`/admin/programs`)
지원사업·교육 공고 → 신청 → 파일 제출 → 검토 흐름이에요.

1. **공고 등록**: 제목·내용·신청기간·제출마감·공고문 첨부. 상태 **작성 중(draft)** 으로 저장해요.
2. **모집 시작**: 상태를 **모집 중(open)** 으로 바꾸면 전체 입주기업에 공지 메일이 가요(메일 발송이 켜져 있을 때. 확인창이 떠요).
3. **신청 관리**: 공고 → "신청 현황"에서 [승인]/[반려] → 결과 메일. 선정된 기업만 자료를 낼 수 있어요.
4. **제출물 검토**: "제출물"에서 파일 확인 → 승인/반려/**재제출 요청**+의견 → 의견 메일. 검토할 제출물 수가 메뉴·홈에 보여요.
5. 제출 마감 3일/1일 전, 미제출 기업에 자동 안내(CRON 설정 필요).

- 신청 기간·제출 마감은 서버가 지켜요(기간 밖 신청·제출 불가).
- 입주기업 포털 업로드는 **파일당 4MB까지**예요. 더 큰 파일은 기업이 센터로 따로 보내도록 안내해요.
- HWP·DOCX 첨부는 자동으로 PDF로 바뀌어 미리보기가 돼요(CloudConvert 설정 필요, 7장).
- 메일이 꺼져 있으면 결과·의견은 메일로 가지 않아요. 기업은 포털 프로그램 화면에서 결과를 봐요.

### 3-8. 메일 (`/admin/emails`)
- **보낸 기록**: 시스템이 보낸 모든 메일을 기간·상태(보냄 / 보내지 못함 / 설정 안 됨)·종류로 봐요. 행을 누르면 받는 사람·제목·오류 내용이 보여요.
- 보내지 못한 메일은 **[같은 내용으로 다시 보내기]** 로 그때 본문을 다시 보내요. **첨부 PDF는 빠지니** 청구서 PDF가 필요하면 청구서 화면에서 받아 따로 전달해요.
- **새 메일**: 입주기업을 골라 제목·본문을 직접 써서 보내요(`{{tenant_name}}` 변수 사용 가능).
- **템플릿**: 자동 발송 메일 8종(계정 안내/청구서/납부 안내/프로그램 공지/선정 결과/제출 요청/검토 결과/문의 알림)의 제목·본문을 고쳐요.
- 메일 발송이 꺼져 있으면(지금 운영 상태) 시도는 "설정 안 됨"으로 기록만 남아요.

### 3-9. 증빙 처리 (`/admin/expenses`, 예전 "사업비 정산")
사업비(정부지원사업) 증빙을 올리고 정리하는 메뉴예요. 관리비 정산과는 별개예요. 하위 탭: **증빙 올리기 · 증빙 내역 · 사업·프로젝트 · 데스크톱 앱 설치**.
- **증빙 올리기**: 파일을 끌어다 놓거나 [파일 추가](휴대폰은 [촬영]). 파일마다 자동 인식해요. 행 상태는 **입력 필요 · 확인 필요 · 준비 완료 · 제외** 4가지이고, "확인 필요"에는 사유(중복 의심·인식 신뢰도 낮음·금액 불일치 등)가 붙어요. 사유마다 [확인했어요]를 누르거나 원본을 보며 고친 뒤 아래 [n건 저장]. 저장 전에는 아무것도 기록되지 않아요. 데스크톱 앱에서 온 증빙도 여기에 모여요(홈 "데스크톱 앱에서 온 증빙 n건").
- 인건비는 파일 없이 [인건비 등록]으로 넣어요(지난달 내역 불러오기 가능).
- **증빙 내역**: 프로젝트별 비목 집행 현황. "점검 필요" 보기, [정산 전 점검], [내려받기](엑셀·원본 zip·인쇄).
- **사업·프로젝트**: 과제 등록(사업계획서·협약서를 올리면 과제명·기간·예산을 자동으로 채워 주고, 저장은 직접 눌러요).

### 3-10. 메신저 (`/admin/messenger`)
사내 메신저예요. "시스템 알림" 토픽에 문의 접수·데스크톱 앱 증빙 도착·관리비 청구서 발행 알림이 자동으로 남아요. 입주기업은 포털 메신저에 게스트로 들어와요.

검증 참고: 기존 엑셀 하단의 "10평당 실계산"은 분모 311평 기준이었으나 실제 행별 청구는 336평어치였습니다(원본 엑셀 내부 불일치). 새 시스템은 분모를 계약에서 자동 산출하므로 기업별 청구액은 동일하고 내부 집계만 더 정확합니다.

## 7. 환경변수 (기능 활성화 스위치)

Vercel 프로젝트 설정(Settings > Environment Variables)에서 관리합니다. **미설정이어도 사이트는 정상 동작**하며 해당 기능만 비활성화됩니다.

| 변수 | 용도 | 현재 | 미설정 시 |
|---|---|---|---|
| `DATABASE_URL` 등 Postgres 계열 | DB 연결 | ✅ 설정됨 | — |
| `BLOB_READ_WRITE_TOKEN` | 파일 저장 | ✅ 설정됨 | — |
| `RESEND_API_KEY` | 메일 발송 | ❌ | 모든 메일이 스킵되고 실패 로그만 기록 |
| `MAIL_FROM` | 발신 주소 (도메인 DNS 인증 필요) | ❌ | 〃 |
| `ADMIN_NOTIFY_EMAIL` | 홈페이지 문의 알림 수신 | ❌ | 문의 알림 메일 없음 (접수는 정상) |
| `CRON_SECRET` | 자동 리마인더 인증 | ❌ | 납부/제출 리마인더·연체 자동 전환 없음 |
| `CLOUDCONVERT_API_KEY` / `CLOUDCONVERT_WEBHOOK_SECRET` | HWP→PDF 변환 | ❌ | 첨부 미리보기 없음 (다운로드는 정상) |
| `APP_URL` | 변환 웹훅·메일 링크 기준 주소 | ❌ | `https://www.puholdings.co.kr` 권장 |
| `BILLING_BANK_INFO` | 청구서 PDF 납부계좌 문구 | ❌ | 기본값: "예금주: ㈜포항연합기술지주 / 하나은행 910-910009-44304" |
| `OPENAI_API_KEY` | 계량기·고지서 사진 자동 판독 | ❌ | 월 마감 1단계의 사진 판독 영역만 비활성화 (직접 입력은 정상) |
| `OPENAI_MODEL` | 판독 모델 지정 (선택) | ❌ | 기본 `gpt-5.6-sol`. 비용을 낮추려면 `gpt-5.6-terra` 또는 `gpt-5.6-luna` |
| `JWT_SECRET` | 로그인 서명키 (선택) | ❌ | DB 비밀번호에서 자동 파생 — **설정 불필요** |

**메일을 켜려면**: Resend(resend.com) 가입 → 도메인 인증(DNS) → API 키 발급 → `RESEND_API_KEY`, `MAIL_FROM`(예: `포항연합기술지주 <noreply@puholdings.co.kr>`), `ADMIN_NOTIFY_EMAIL` 추가 → 재배포.

**사진 자동 판독을 켜려면**: platform.openai.com 가입 → 결제수단 등록 → API 키 발급 → Vercel에 `OPENAI_API_KEY` 추가 → 재배포. 월 마감 때만 쓰므로 비용은 한 달에 수백 원 수준입니다. 더 낮추려면 `OPENAI_MODEL=gpt-5.6-terra`를 함께 설정하세요(정확도가 조금 떨어질 수 있으니 판독값 확인을 더 신경 쓰세요).

## 8. 기술 운영 정보 (개발 담당자용)

| 항목 | 내용 |
|---|---|
| 저장소 | github.com/keilvher1/puholdings (main 브랜치) |
| 호스팅 | Vercel — 프로젝트 `puholdings` / `vercel --prod`로 배포 |
| DB | Neon Postgres (Vercel 연동) — raw SQL, `lib/db.ts`의 `getDb()` |
| 파일 | Vercel Blob (private) + `/api/file` 프록시 |
| 마이그레이션 | `scripts/migrations/*.sql` → `DATABASE_URL=... node scripts/run-migration.mjs <파일>` (전부 멱등, 적용 완료) |
| 테스트 | `pnpm test` — 관리비 계산엔진 실측값 검증 9건 |
| 개발 컨벤션 | 저장소 루트 `CLAUDE.md` 참고 |
| 청구서 PDF | `@react-pdf/renderer` + Pretendard 폰트(`public/fonts/`) |
| 관리자 비밀번호 재설정 | DB `admins.pass_hash`를 bcrypt 해시로 갱신 (개발 담당자 작업) |

### 보안 메모
- `/api/admin/setup`: 관리자가 이미 존재하면 로그인 없이 계정 생성 불가 (2026-07-21 적용)
- 포털은 세션의 기업 ID로만 데이터 접근 (타 기업 청구서/파일 접근 시 404)
- 첨부 경로 이동(`..`) 차단, 청구서 PDF는 관리자/해당 기업만 다운로드 가능
- 로그인 토큰 서명키는 `JWT_SECRET` 미설정 시 DB 비밀에서 파생 (소스코드에 비밀 없음)
